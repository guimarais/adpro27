## Why

Students need to turn the working local data application into a service another
person can use and distinguish tested code, hosting updates, and actual handover
evidence. The confirmed interview keeps implementation supplied and student edits
tiny, with the complete class distribution at each student's repository root.

## What Changes

- Add five standalone ordered notebooks, six references, a thin Streamlit UI,
  locked environment/workspace, saved diagnostics, and hosting/configuration guide.
- Reuse the active class-05 Observation/data/read-only harness and meaningful tests.
- Supply one root-layout student Actions job for locked offline tests and Ruff.
- Keep the public data/replay app usable without AI credentials; optional private
  live configuration retains bounded execution and honest access/cost limits.
- Supply optional local Podman packaging within the separate enrichment budget.
- Integrate the agreed 45-minute preparation/90/210 budgets into the verifier and
  authoring/curriculum/status records, keeping delivery checks separate.

## Capabilities

### New Capabilities
- `class-06-content`: Deployment and automated delivery using supplied code,
  root-layout student repositories, safe configuration, and actual release evidence.

### Modified Capabilities
None in the main spec tree. Existing classes keep their workload/contracts.

## Impact

Adds course content and extends the instructor verifier. Does not publish an app,
create accounts/repositories, commit/push, add a model dependency to required
completion, change project assessment, or track root legacy content. Real hosted
CI/deployment, desktop interaction, optional live/container, and platform/timing
checks require their own evidence.
